# QA — V0.5.4 Three-Card Artwork Viewer

**Risk:** MEDIUM  
**QA status:** Static/package checks pass in the prepared patch package. Real-device acceptance is still required after applying/deploying the patch.

## Static checks

- New viewer JavaScript parses successfully with `node --check`.
- Patch installer parses successfully with Python.
- Installer verifies the expected V0.5.3 baseline hashes before editing runtime files.
- Installer refuses to proceed when baseline files differ, preventing accidental application onto stale or advanced runtime code.
- V0.5.4 version-coherence checks cover `index.html`, `js/app.js`, and `sw.js`.
- Service Worker app shell explicitly includes the new viewer CSS and JavaScript.
- Root Patch Manifest advances to V0.5.4 and V0.5.3 root manifest is removed during application.
- Checksums are regenerated after all release files are finalized.

## Real-device acceptance checklist

1. Complete a fresh Three-Card Reading.
2. Open Past, Present and What May Unfold Next artwork one by one.
3. Confirm each enlarged image matches the tapped card.
4. Confirm enlarged scale feels comparable to single-card mode and retains visible margin around the card.
5. Close via ×.
6. Reopen and close via backdrop tap.
7. On a hardware/desktop keyboard, confirm Enter/Space opens, Escape closes, Tab stays inside the viewer, and focus returns correctly.
8. Switch TH ↔ EN and confirm accessibility/title behavior remains correct.
9. Confirm page position does not jump after closing.
10. Confirm mini player/audio continues according to existing V0.5.3 behavior and is not restarted or paused by the viewer.
11. Confirm Save Image and Share are unchanged.
12. Leave and return to Three-Card on the same local day; same cards and same narrative remain restored.
13. Confirm Daily and Ask still open and behave normally.
14. Confirm installed PWA reports BUILD 0.5.4 after cache/deployment propagation.

Do not label iOS/Android/production PASS until those checks are actually performed on the relevant devices.
